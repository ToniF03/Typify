# TypifyTextbox control manual

`TypifyTextbox` is a small, reusable WPF class library for editing Typst source. Its public control is `Typify.TextBox.TypifyTextbox`, a subclass of `System.Windows.Controls.RichTextBox`. The project targets .NET Framework 4.7.2 and has no reference to the Typify application, Gitify, Typst CLI, or third-party packages.

| Property | Value |
| --- | --- |
| Assembly | `TypifyTextbox.dll` |
| Namespace | `Typify.TextBox` |
| Control | `TypifyTextbox` |
| Base type | `RichTextBox` |
| Target | .NET Framework 4.7.2 / WPF |

Add a project reference to `TypifyTextbox/TypifyTextbox.csproj` (or a reference to the built assembly). The host must itself run on Windows and reference the WPF assemblies `PresentationFramework`, `PresentationCore`, `WindowsBase`, and `System.Xaml`.

## XAML usage

Declare the CLR namespace and assembly, then place the control in a WPF view:

```xml
<Window
    xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
    xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
    xmlns:typify="clr-namespace:Typify.TextBox;assembly=TypifyTextbox">
    <typify:TypifyTextbox Text="{Binding SourceText, Mode=TwoWay}"
                          IsDarkTheme="False"
                          ShowBorder="True"
                          IsHorizontalScrollEnabled="True" />
</Window>
```

`Text` binds two-way by default, so a binding can also omit `Mode=TwoWay`:

```xml
<typify:TypifyTextbox Text="{Binding SourceText}" />
```

The control is a rich-text WPF editor underneath. The public string property makes ordinary text editing and binding convenient. The inherited `RichTextBox.Document` property is still available to hosts that need direct WPF document access; the library adds no separate document serialization API.

## Public API

| Member | Kind | Default | Behavior |
| --- | --- | --- | --- |
| `Text` | Dependency property / `string` | Empty string | Reads and sets the source text. Two-way binding by default. Programmatic changes replace the document text. |
| `ShowBorder` | Dependency property / `bool` | `true` | Sets `BorderThickness` to one unit or zero. It does not change `BorderBrush`. |
| `IsDarkTheme` | Dependency property / `bool` | `false` | Selects the highlighter's light or dark syntax palette and schedules recoloring. The host remains responsible for base foreground/background colors. |
| `IsHorizontalScrollEnabled` | Dependency property / `bool` | `true` | Maps to horizontal scrollbar visibility `Auto` or `Disabled`. |
| `IsWordWrapEnabled` | CLR property / `bool` | Derived from the document page width | `true` sets document page width to at least 300 units (or the current control width); `false` sets it to 100000 to allow long lines. It is not a dependency property and cannot be used as a normal WPF binding target. |

The control also inherits `RichTextBox` members, including `TextChanged`, `Selection`, `CaretPosition`, `AcceptsTab`, and normal WPF brushes, font, padding, and scroll properties.

Basic code-behind use:

```csharp
editor.Text = "= Report\n\n#let answer = 42";
string source = editor.Text;
editor.IsDarkTheme = true;
```

## Text synchronization

The `Text` dependency property and the internal WPF document are synchronized in both directions:

1. Setting `Text` normalizes line endings to Windows paragraph breaks and replaces the document contents when they differ.
2. User edits read text from the `FlowDocument`, remove the final paragraph terminator generated by WPF, and update `Text`.
3. Internal flags prevent document/property synchronization and syntax formatting from recursively triggering text synchronization.
4. Text is exposed using line-break-normalized content; callers should not rely on preserving the exact original CRLF/LF encoding.

Programmatically setting the full `Text` value replaces the document and may reset the caret/selection. For incremental editing, let the user type in the control rather than reassigning the entire property after every keystroke.

## Syntax highlighting

`TypstLexer` is a private lightweight lexer in `TypifyTextbox.cs`. After source changes, a background-priority `DispatcherTimer` waits 35 ms before recalculating spans and applying foreground, bold, or italic formatting to the document. A theme change queues the same recoloring pass. Highlight formatting is applied to WPF text ranges, not to the underlying source text.

The current lexer recognizes:

| Construct | Visual treatment |
| --- | --- |
| Typst code marker `#` and following identifier | Marker color; keywords and function-like names have dedicated colors. |
| Keyword set (`let`, `set`, `show`, `if`, `for`, `import`, `include`, booleans, and others) | Keyword color. |
| Identifier after `#` followed by `(` | Function color; this is a syntactic guess, not symbol resolution. |
| Double-quoted strings | String color. Backslash escapes are considered when locating the end quote. |
| Numeric literals and adjacent letters, `%`, or periods | Number color. This is lexical token coloring, not Typst type/unit validation. |
| `//` and `/* ... */` comments | Comment color. Block comments may span lines. |
| `$...$` math spans on one line | Math color and italic style. The lexer does not extend a math span across line breaks. |
| Inline backticks and triple-backtick raw spans | Raw color; triple-backtick fenced content is colored line by line. |
| `@label` and `<label>` references | Reference color. |
| A line beginning with one or more `=` followed by a space | Marker color for the equals signs; heading color and bold style for the rest of the line. |
| Leading `- `, `+ `, and `/ ` markers | Marker color and bold style. |
| `**...**`, `*...*`, and `_..._` emphasis spans | Heading color/bold for double and single asterisks; math color/italic for underscores. |

The light and dark palettes are defined in the `LightPalette` and `DarkPalette` fields. The host can use the `Foreground` property for ordinary uncolored text and set a matching `Background`; `IsDarkTheme` only selects syntax colors.

Palette values by category:

| Category | Light | Dark |
| --- | --- | --- |
| Heading | `#0000FF` | `#569CD6` |
| Marker | `#AF00DB` | `#C586C0` |
| Keyword | `#0000FF` | `#C586C0` |
| Function-like identifier | `#795E26` | `#DCDCAA` |
| String | `#A31515` | `#CE9178` |
| Number | `#098658` | `#B5CEA8` |
| Comment | `#008000` | `#6A9955` |
| Math / single-star emphasis | `#AF00DB` | `#DCDCAA` |
| Raw text | `#A31515` | `#CE9178` |
| Reference | `#267F99` | `#4EC9B0` |

This is intentionally not a full Typst grammar. It does not resolve identifiers, parse nested expressions, validate markup, report errors, or guarantee correct coloring for every valid/invalid source. A change in the Typst language may require lexer updates.

## Styling and scrolling

Default constructor settings are:

- `AcceptsTab = true`.
- Vertical scrollbar set to `Auto`; horizontal scrollbar set to `Auto` unless disabled through `IsHorizontalScrollEnabled`.
- Consolas, 14 pt, 10 unit padding.
- Light foreground `#333333`, background `#FFFFFF`, and border brush `#E5E5E5`.
- WPF spell checking disabled.

Hosts can override ordinary inherited properties in XAML or code. `ShowBorder` controls only border thickness. To switch the editor palette, update the host's base brushes and set `IsDarkTheme` to the same theme state.

Example theme handling:

```csharp
 editor.Foreground = isDark ? new SolidColorBrush(Color.FromRgb(204, 204, 204)) : new SolidColorBrush(Color.FromRgb(51, 51, 51));
 editor.Background = isDark ? new SolidColorBrush(Color.FromRgb(30, 30, 30)) : Brushes.White;
 editor.BorderBrush = isDark ? new SolidColorBrush(Color.FromRgb(43, 43, 43)) : new SolidColorBrush(Color.FromRgb(229, 229, 229));
editor.IsDarkTheme = isDark;
```

## Known limitations

- No line numbers, minimap, bracket matching, folding, completion, hover information, diagnostics, formatting, or language-server integration.
- No Markdown rendering or preview, file I/O, Typst compiler integration, PDF rendering, or project management. Those belong to the host app or other projects.
- Highlighting runs over the text document using a `RichTextBox`; very large documents can make full-document recoloring noticeable.
- `IsWordWrapEnabled` is a plain CLR property. It has no dependency-property change notification for bindings and it sets the page width at the time it is assigned rather than tracking every future resize.
- The control does not retain the source file's original newline encoding.

## Build

Build `TypifyTextbox/TypifyTextbox.csproj` with Visual Studio/MSBuild and the .NET Framework 4.7.2 developer pack. The project compiles a single source file and references only framework/WPF assemblies; it does not need Typst, Git, network access, or NuGet packages at build time.
